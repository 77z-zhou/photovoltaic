# 光储以租代建数字化直租平台 MVP 规格

## Problem Statement

项目公司计划通过“以租代建”模式建设光伏/储能电站：项目公司投建并持有电站资产，工商业客户零投入使用，代理商负责客户开发和现场协同，建设运维方完成勘测/施工/验收，资金方提供融资并参与还款对账。当前没有可运行的系统，客户申请、屋顶和电费资料、风控审批、电子签约、项目建设、并网运营、节余电费账单、代扣、资金方协同和资产结清无法形成统一的数据闭环。

客户提供的参考截图体现了“首页、工作台、待办、账户、关于平台”的视觉语言，但不覆盖本项目完整的融资租赁和电站生命周期，因此截图只作为视觉与信息密度参考，业务范围以本规格和已批准的 ADR 为准。

## Solution

建设一套可演示、可测试、带后端持久化和权限控制的模块化单体平台，覆盖：

- 终端客户微信/支付宝小程序：自主申请、资料上传、项目进度、合同、账单、消息和客服。
- 代理商微信小程序：客户代提交、客户列表、项目流程、勘测/施工任务、验收材料、渠道结算和待办。
- 运营管理后台：客户与项目、风控审批、合同、项目生命周期、账单/资金结算、资产、能源监控、风险和报表。
- 资金方轻量入口：项目报送、补件、放款确认、还款计划和对账信息。

第一版使用模拟外部服务验证完整闭环；真实支付、电子签、征信、IoT、电网和资金方生产接入在供应商、资质和账号确定后，通过对应 Adapter 替换。

## User Stories

1. 作为终端客户，我希望提交企业信息、联系人信息、站点地址、屋顶照片和电费单，以便申请以租代建项目。
2. 作为终端客户，我希望查看资料是否完整以及待补充内容，以便及时修正申请。
3. 作为终端客户，我希望查看项目从申请到结清的进度，以便知道下一步和预计时间。
4. 作为终端客户，我希望预览合同、完成模拟实名/签字并下载归档合同，以便确认租赁关系。
5. 作为终端客户，我希望查看每月账单、节余电费明细、代扣结果和逾期提醒，以便安排付款。
6. 作为终端客户，我希望查看电站发电量、用电节省和碳减排等运营信息，以便了解项目收益。
7. 作为终端客户，我希望在签约失败、扣款失败或资料被驳回时看到清晰原因和可执行的下一步，以便恢复流程。
8. 作为代理商成员，我希望在本组织内创建客户组织和项目，以便代客户提交资料。
9. 作为代理商成员，我希望查看本组织所有客户和项目的跟进状态，以便安排销售和现场工作。
10. 作为代理商成员，我希望接收勘测、施工、补件和验收待办，以便按生命周期推进项目。
11. 作为代理商成员，我希望上传现场照片、勘测结果、施工进度和验收材料，以便运营人员审核。
12. 作为代理商成员，我希望查看渠道费用、持续分润和对账单，以便核对收益。
13. 作为运营人员，我希望查看项目全流程看板和待办，以便把项目推向下一状态。
14. 作为运营人员，我希望建立客户组织、站点和项目档案，并记录跟进、材料和状态变化，以便形成完整项目记录。
15. 作为风控人员，我希望根据资料完整性、企业信息、用电数据和模拟信用结果审批或要求补件，以便控制项目风险。
16. 作为风控人员，我希望提交人不能审批自己的申请，并且每次审批都有原因和审计记录，以便保持职责分离。
17. 作为项目/施工人员，我希望领取勘测、施工和验收任务，提交进度与材料，以便现场交付可追踪。
18. 作为运维人员，我希望查看已并网电站、设备在线状态、发电量和异常，以便处理运营问题。
19. 作为财务人员，我希望生成固定分期或动态能源账单，查看代扣、对账、逾期和调整单，以便管理回款。
20. 作为财务人员，我希望原账单不能被覆盖，错误必须通过调整单处理，以便保留结算历史。
21. 作为财务人员，我希望在期数完成、账单付清、无欠费/待调整后确认结清，以便触发资产结清和归档。
22. 作为资金方，我希望接收项目报送、补件通知、放款确认、还款计划和对账信息，以便管理融资项目。
23. 作为超级管理员，我希望配置角色、组织、模拟服务场景、费率参数和演示数据，以便支持测试和应急管理。
24. 作为任何授权用户，我希望只能看到自己组织和项目范围内的数据，以便保护客户和资金信息。
25. 作为平台维护人员，我希望所有外部回调可验签、幂等、重试并关联原始报文，以便处理异步结果和供应商异常。
26. 作为客户评审人员，我希望使用内置多角色账号和可重置数据重复演示成功/异常流程，以便验证平台是否满足业务需求。
27. 作为开发人员，我希望模拟 Adapter 和未来真实 Adapter 遵守同一内部 Interface，以便替换供应商而不修改项目、合同和账单模块。
28. 作为测试人员，我希望通过 API 和端到端剧本验证状态、权限、账单和回调行为，以便在每个阶段稳定回归。

## Implementation Decisions

- 采用 TypeScript 全栈：Taro 承载微信/支付宝小程序，React/Next.js 承载运营后台，NestJS 承载后端。
- 采用模块化单体，不按三端拆成微服务。核心模块包括身份与权限、客户组织与联系人、站点/屋顶、项目与生命周期、勘测与施工验收、风控与审批、合同与电子签、账单与代扣、电站资产与能源数据、资金方与渠道结算、通知/文件/审计。
- 项目模块拥有项目状态和状态转移；账单模块拥有账单生成、调整和结清判断；合同模块拥有合同版本和签署状态；其他模块通过明确 Interface 协作。
- 统一项目状态链为：`草稿 → 已提交 → 勘测中 → 待审批 → 审批通过 → 待签约 → 建设中 → 待验收 → 已并网 → 运营中/还款中 → 已结清`。
- 资料补充回到资料提交；审批拒绝默认终止但可由有权限人员重新发起；签约失败回到待签约；验收驳回回到建设中；扣款失败不回退项目状态，只影响账单、重试和催收；取消项目为明确终止状态。
- 状态只能由授权人工操作或验证过的系统事件触发；每次转移记录来源、时间、原状态、新状态、原因、关联材料和外部请求号。
- 客户数据层级为“客户组织 → 联系人 → 站点/屋顶 → 项目”；代理商按组织隔离；后台专业角色独立分权，关键操作禁止提交人自审。
- 三端使用同一套版本化 REST API，以 OpenAPI 作为契约，返回数据按角色和权限裁剪。
- PostgreSQL 保存关系型业务数据和外键；对象存储保存屋顶照片、电费单、合同和验收材料；Redis 仅用于缓存、限流和异步任务。
- 供应商原始报文和可变扩展字段放在隔离记录中；微信/支付宝、电子签、支付、征信、IoT、电网和资金方均使用 Provider Interface + Adapter。
- 关键写操作在同一事务中写业务数据和 Outbox 事件；统一回调接收模块负责验签、幂等、保存原始报文和触发内部事件。
- 演示账号使用服务端会话/JWT；微信、支付宝登录作为独立身份 Adapter 绑定内部联系人。
- 固定账单按合同生成固定应付金额；动态能源结算按自然月冻结能源数据快照，基于原电网成本、使用电站后的实际成本和合同参数计算节余电费。电价、自用比例、上限和取整规则配置化。
- 原账单不可覆盖；能源数据或计量错误使用账单调整单，保留原账单、原因、依据、金额变化和审批人。
- 采用私有对象存储、短时签名链接、敏感数据最小化、默认脱敏、结构化日志、关联 ID、可恢复备份和配置化留存策略。
- 每阶段通过 Docker Compose 启动，并提供演示账号、测试数据、运行说明和已知限制。
- 交付顺序为：基础平台 → 内部业务闭环 → 终端客户体验 → 结算与外部能力模拟 → 后台完善与最终验收。

## Testing Decisions

- 主测试 Seam 是版本化 REST/OpenAPI 应用接口；测试外部行为、权限、状态、错误、幂等和结算结果，不测试 ORM、控制器内部实现或具体供应商 SDK 的细节。
- 单元测试覆盖项目状态转移、权限判断、账单计算、调整单和结清条件。
- 模块集成测试覆盖 PostgreSQL、对象存储、Outbox、回调处理、任务重试和审计记录。
- API 契约测试覆盖 OpenAPI 请求/响应、角色数据裁剪、错误码、幂等键和异步状态。
- 关键流程 E2E 测试覆盖客户自主申请、代理商代提交、资料补充、审批拒绝、签约失败、验收驳回、扣款失败、重试、调整单和最终结清。
- 三端只做关键路径冒烟测试：页面可访问、表单可提交、状态可展示、错误可解释；业务规则集中在 REST Seam 验证。
- 测试和演示使用幂等的 `seed:demo` / `reset:demo`，确保账号、组织、项目、账单、回调和异常场景可重复初始化。
- 继承当前仓库无既有测试的事实，不假设已有测试工具或 prior art；建立测试基础设施后，新增模块必须从外部行为测试开始。

## Out of Scope

- 用户社区、积分、理财、续约、加装和电站转让等深度增值运营功能。
- 设备远程控制、固件升级、参数下发和运维专用调试工具。
- 第一版真实支付、电子签、征信、IoT、电网和资金方生产接口上线。
- 多项目公司的 SaaS 租户隔离和跨法人部署；数据模型保留扩展空间，但第一版服务单一项目公司、多代理商、多项目和多资金方。
- 生产级 Kubernetes、多地域高可用、复杂灾备和监管报送自动化。
- 客户最终品牌、Logo、合同模板、费率和供应商选择；这些需要客户后续提供正式资料。

## Further Notes

- 已批准的长期取舍见 ADR-0001、ADR-0002、ADR-0003。
- 外部服务边界研究已确认：微信/支付宝平台能力必须独立适配；真实接入依赖主体资质、账号、密钥、白名单、回调和商务协议。
- 客户参考界面原型的获选组合为：客户端移动任务流、代理商角色工作台、运营后台全流程指挥台。原型保存在独立的 `prototype/ia-visual` 分支，仅作为视觉和信息架构决策依据。
- 该规格是从 Wayfinder 地图收敛出的开发起点；规格获批后使用 `to-tickets` 拆成端到端 tracer-bullet 票据，再进入 `implement`。
