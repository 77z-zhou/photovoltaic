# 双小程序与外部服务接入边界研究

> 对应 GitHub Issue：[#2 核实双小程序与外部服务的接入边界](https://github.com/77z-zhou/photovoltaic/issues/2)
>
> 研究日期：2026-09-03。本文只锁定架构边界，不替客户选择具体电子签、征信、逆变器、电网或资金方供应商。

## 结论摘要

1. **业务域可以共享，平台能力不能假设共享。** 项目、客户、合同、账单、项目状态机、审批和通知编排应放在同一套服务端领域模型；微信/支付宝端的登录、身份授权、上传、支付/代扣、活体/人脸、消息和应用配置必须通过平台适配层实现。
2. **所有外部服务都应走 provider port + adapter。** 电子签、征信、IoT、电网和资金方均没有可直接假定的统一公共 API。先定义内部稳定接口，再为选定供应商实现适配器；模拟服务实现同一接口和同一状态/回调契约。
3. **回调是一级业务入口。** 支付、代扣、电子签、征信异步结果、IoT 数据同步和资金方放款/对账都可能异步返回。需要公网 HTTPS 接收端、签名验真、幂等键、原始报文留存、重试和人工补偿；前端不能直接把“调用成功”当作业务完成。
4. **真实接入的前置条件尚未满足。** 至少需要项目公司/商户主体、融资租赁或合作持牌机构资质、微信/支付宝小程序和商户账号、电子签及征信服务合同、设备云账号、电网地区与客户授权、资金方接口协议。MVP 可用模拟服务先验证流程，但模拟接口必须保留真实接入所需的状态和回调字段。

## 双小程序边界

### 微信小程序

微信官方登录流程是：小程序调用 `wx.login()` 获取一次性 `code`，服务端调用 `auth.code2Session` 换取 `OpenID`、可用时的 `UnionID` 和 `session_key`；`session_key` 不应下发到小程序，`code` 只能使用一次。因此登录必须由微信适配器和服务端完成，领域层只接收平台无关的 `externalUserId`/绑定关系。

微信的 `web-view`/业务域名要求在小程序后台配置，域名必须使用 HTTPS、完成 ICP 备案且不能使用 IP；官方文档还限制域名数量和生效条件。文件上传、业务 API、电子签 H5 等地址应集中在可配置的域名清单，不能把任意供应商 URL 写死在共享前端。

微信支付的 JSAPI/小程序下单由服务端调用，要求商户身份、API 签名和 `notify_url`；支付成功通知需要验签并按订单号幂等处理。微信支付分的“创单结单合并”文档也明确了商户回调地址和免密代扣结果回调。支付相关能力应单独放在微信支付适配器，不能复用支付宝的签约字符串或状态码。

来源：

- [微信小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)
- [微信业务域名](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/domain.html)
- [微信支付 JSAPI/小程序下单](https://pay.weixin.qq.com/wiki/doc/apiv3/apis/chapter3_1_1.shtml)
- [微信支付分创单结单合并接口](https://pay.weixin.qq.com/wiki/doc/apiv3/apis/chapter6_1_1.shtml)

### 支付宝小程序

支付宝 `my.getAuthCode` 返回一次性 `authCode`，由小程序服务端向支付宝换取 `user_id/open_id` 或已获隐私授权的用户字段。官方要求在开放平台的隐私申请中按字段申请权限；授权码一次有效并有有效期，且 `web-view` 中不能直接调用该 API。支付宝因此需要自己的授权、隐私申请和服务端换码适配器。

支付宝周期扣款的 `my.paySignCenter` 仅支持**企业支付宝小程序**，且接入流程要求绑定商家账号、开通周期扣款产品、服务端生成 `signStr`，并配置接口加签、应用网关和支付宝网关。签约结果可能为成功、未知或失败；官方明确未知结果要通过服务端查询协议状态。文档还给出额度和周期限制（单笔不超过 100 元、日不超过 1,000 元、月不超过 30,000 元，周期最短 7 天），所以“节余电费按月代扣”不能直接按客户方案假设上线，必须先核实产品适用性和金额规则。

支付宝开发设置要求每个应用单独配置公私钥/证书，应用网关用于异步通知，敏感接口可配置 IP 白名单，HTTP 请求和文件上传受服务器域名白名单约束。支付宝和微信的 `appId`、密钥、用户标识、签名和回调均不可混用。

来源：

- [支付宝 `my.getAuthCode`](https://opendocs.alipay.com/mini/api/openapi-authorize)
- [支付宝 `my.paySignCenter`（周期扣款）](https://opendocs.alipay.com/mini/006v6d?pathHash=eb9b74e0)
- [支付宝小程序开发设置（加签、网关、IP 白名单、域名）](https://opendocs.alipay.com/mini/03m2a7.md)
- [支付宝小程序创建与绑定商家](https://opendocs.alipay.com/mini/03m091.md)

### 可共享与必须适配的清单

| 能力 | 共享部分 | 必须适配的部分 |
| --- | --- | --- |
| 登录/用户绑定 | 内部用户、客户、授权记录模型 | 微信 `wx.login`/`code2Session`；支付宝 `my.getAuthCode`/OpenAPI 换码 |
| 页面/业务流程 | 项目状态、表单 schema、合同/账单展示、错误码 | 小程序生命周期、路由、组件、隐私授权交互 |
| 图片/电费单上传 | 文件元数据、对象存储 key、审核状态 | `wx.chooseImage`/上传接口与支付宝 `my.chooseImage`/上传接口、大小和域名限制 |
| 电子签 | 合同、签署方、签署状态、归档记录 | 各供应商 SDK/H5、实名认证/人脸能力、签署回调 |
| 收款/代扣 | 账单、扣款任务、支付状态、对账模型 | 微信支付/支付分与支付宝协议签约、扣款、查询、通知 |
| 消息 | 业务通知模板和发送策略 | 微信订阅消息、支付宝消息/模板、用户授权和模板审核 |

## 外部服务边界与资质约束

### 电子签（e 签宝/法大大/契约锁等）

电子签供应商通常将“发起签署、实名/身份核验、签署页面、状态查询、文件归档和异步通知”拆开。e 签宝官方开放文档同时提供 SaaS API、认证服务 API 和文件签署 API，说明这不是一个只在小程序端调用的 UI SDK；应由服务端持有 API 凭证并统一接收回调。具体的企业认证、签署主体、模板、印章和计费需以客户选定供应商的入驻审核为准。

架构要求：`EContractProvider` 至少包含创建签署流程、获取签署入口、查询状态、下载归档件、撤销/作废和验签回调；回调事件要能表达签署中、已完成、拒签、超时、身份核验失败和文件归档失败。小程序只打开供应商返回的安全签署入口，不保存供应商密钥。

来源：

- [e 签宝开放平台 API 文档](https://open.esign.cn/doc/opendoc/pdf-sign3/aqc0s4)
- [e 签宝认证服务 API 对接指南](https://open.esign.cn/opendoc/identity_service/shiming)
- [中华人民共和国电子签名法（中国政府网）](https://www.gov.cn/flfg/2011-04/28/content_1854046.htm)

### 代扣和支付

代扣不是普通“支付按钮”：需要商户/收款主体、产品开通、协议签约、扣款指令、异步通知、撤销/解约、失败重试和对账。支付宝周期扣款的签约字符串由服务端生成，结果存在“未知”状态；微信支付文档要求 `notify_url` 并验证通知签名。内部支付端口应使用 `agreementId`、`providerTransactionId`、`idempotencyKey`、`status` 和 `failureReason` 等中立字段。

客户材料提到的“微信支付分/代扣”不能当作已确认产品：需根据融资租赁场景和金额/周期向微信支付商务确认可用产品、商户资质及是否允许服务商模式。支付宝单笔/月度额度限制尤其需要业务方先确认月度节余电费是否会超限。

### 征信、芝麻信用和风控

征信数据不是通用的免费 API。企业征信或个人信用分通常需要与持牌征信机构/平台签约、完成主体和场景审核、取得客户授权，并遵守征信业务和个人信息处理规则。支付宝官方用户信息文档也要求在开放平台先完成隐私字段申请；客户方案中“芝麻信用分、蚂蚁风控接口、企业征信”应拆成不同 provider，不能设计成一个固定字段。

架构要求：风控服务只接收最小必要数据，记录授权凭证、数据来源、评分版本、命中规则和有效期；供应商返回的原始敏感数据应隔离存储，业务只消费标准化风险结论。模拟服务应支持通过、拒绝、需人工复核、供应商超时和授权不足等结果。

来源：

- [中国人民银行征信中心](https://www.pbccrc.org.cn/)
- [征信业管理条例（中国政府网）](https://www.gov.cn/zhengce/content/2013-01/29/content_2319601.htm)
- [支付宝隐私申请及使用基础规则](https://opendocs.alipay.com/common/02kkuu)
- [个人信息保护法（中国政府网）](https://www.gov.cn/xinwen/2021-08/20/content_5631790.htm)

### IoT/逆变器云

MQTT 是通用消息协议，但它不定义华为、阳光电源、古瑞瓦特等厂商的设备资产模型、指标命名、租户权限、历史数据 API 或控制权限。客户材料所说的“调用逆变器云 API”因此必须先选定设备品牌/云平台并取得正式开发者账号。设备云 API 和电表数据同步应由 `EnergyProvider`/`DeviceProvider` 适配器承接，统一输出站点、设备、时间序列、采样质量和离线状态。

第一版只做监控展示时，建议只开放只读数据：发电量、上网电量、自用电量、设备在线状态和时间戳；远程控制、固件升级、参数下发和调试工具另行审批。模拟服务应支持缺测、延迟、重复、设备离线和计量修正，避免把 IoT 当成永远成功的同步查询。

来源：

- [OASIS MQTT Version 5.0 标准](https://docs.oasis-open.org/mqtt/mqtt/v5.0/mqtt-v5.0.html)
- [国家能源局](https://www.nea.gov.cn/)
- [国家电网有限公司](https://www.sgcc.com.cn/)

### 电网、余电上网和电费结算

电网接口按省份、供电公司、并网类型和客户授权变化，不能在核心域中假定一个全国统一 API。并网申请、计量、电费账单、余电上网结算可能仍需人工或线下系统完成；即使存在地方线上接口，也会有独立账号、证书、白名单和业务审核。

架构上把电网接入定义为可选 `GridProvider`：同步并网/户号/计量数据，或导入经确认的账单文件；记录来源、账期、抄表时间、计量单位、修订版本和人工确认人。能源账单计算只能依赖已确认的数据快照，不应直接依赖实时 IoT 值覆盖历史账单。

来源：

- [国家能源局](https://www.nea.gov.cn/)
- [国家电网有限公司](https://www.sgcc.com.cn/)
- [分布式光伏发电开发建设管理办法等能源政策入口（国家能源局）](https://www.nea.gov.cn/)

### 资金方

银行、保理、融资租赁公司和绿色基金的报送、放款确认、还款对账接口属于双边协议，没有可替代的统一标准。接口形态可能是 SFTP/批量文件、HTTPS API、专线或人工门户；认证可能使用 mTLS、签名、IP 白名单和机构级账号。项目公司是否持有融资租赁资质，或由持牌机构合作，也会影响合同主体、收款主体和数据传输范围。

架构要求：定义 `FundingProvider` 的项目报送、资料补件、授信/审批结果、放款确认、还款计划、回款对账和差错处理端口；每个资金方独立配置字段映射和凭证。第一版可用 CSV/API 模拟，但必须保留批次号、资金方项目号、放款状态、对账状态和拒绝原因。

## 模拟服务接口建议

模拟服务不是把页面按钮固定成“成功”，而是实现与真实适配器相同的端口和状态机：

- 每次请求生成 `requestId`，外部对象保存 `providerObjectId` 和 `provider`。
- 所有写操作支持幂等键；重复回调不会重复签约、扣款、放款或生成账单。
- 状态至少覆盖 `PENDING`、`SUCCEEDED`、`FAILED`、`UNKNOWN`、`CANCELLED`，并保存可重试性。
- 提供可配置场景：授权拒绝、资质未开通、签名错误、超时、限流、回调延迟/重复、扣款失败、设备离线、征信需人工复核、资金方补件。
- 回调以本地事件投递器模拟，测试验签、重试、乱序和最终一致性；业务状态只能由服务端回调/查询确认。
- 真实凭证、证书、商户密钥和个人敏感资料不进入模拟数据或前端包。

建议的最小端口：

```text
PlatformIdentityProvider
  exchangeLoginCode(code) -> externalUserId, session
  requestConsent(scope) -> consentId

PaymentProvider
  createOrder(invoice, channel) -> providerOrderId, clientPayload
  createDebitAgreement(customer, terms) -> agreementId, signPayload
  debit(agreementId, invoice) -> debitId, status
  query(id) -> status
  handleCallback(rawRequest) -> domainEvent

EContractProvider / CreditProvider / EnergyProvider / GridProvider / FundingProvider
  同样采用 create/query/callback（以及领域所需的撤销、对账、补件）模式
```

## 在锁定技术架构前必须向客户确认

1. 微信和支付宝各自的小程序主体、AppID、商户号、服务器域名和备案情况。
2. 收款/代扣主体、融资租赁资质或合作持牌机构，以及支付宝周期扣款金额限制是否适用于本业务。
3. 电子签、征信、逆变器云、电网和资金方的首选供应商、测试账号、合同/授权和回调白名单。
4. 首批设备品牌、并网省份/供电公司、客户是否能提供电费账单或授权查询。
5. 生产环境要求：密钥托管、IP 白名单、mTLS、日志留存、隐私政策、数据出境/共享和监管报送。
