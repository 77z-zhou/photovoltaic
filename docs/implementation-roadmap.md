# 光储直租平台实施路线

## 交付原则

每个阶段都必须在 Docker Compose 演示环境中启动，并提供演示账号、可重置测试数据、运行说明和已知限制。阶段验收通过后才进入下一阶段；最终验收以真实业务剧本为准，而不是只看页面或接口是否存在。

## 阶段一：基础平台

- TypeScript monorepo 与模块化单体骨架
- NestJS 后端、PostgreSQL、对象存储、Redis、Docker Compose
- 服务端会话/JWT 演示登录
- 角色、组织、项目范围授权
- 文件上传与私有访问
- OpenAPI 版本化契约
- 结构化日志、关联 ID、审计记录、Outbox 基础设施
- `seed:demo` 与 `reset:demo` 命令

阶段门槛：所有演示账号可登录；越权访问被拒绝；文件不能通过公开 URL 访问；数据库和对象存储可重置。

## 阶段二：内部业务闭环

- 客户组织、联系人、代理商组织、站点/屋顶、项目
- 项目生命周期和异常状态机
- 勘测资料、施工任务、验收材料
- 风控审批与人工复核
- 合同草稿、版本和签署模拟
- 通知、待办和审计查询

阶段门槛：代理商代提交和运营录入都能创建同一项目；正常流程能到待签约/建设中/待验收；补件、拒绝、签约失败和验收驳回可按规则恢复或终止。

## 阶段三：终端客户体验

- 微信/支付宝小程序共享业务模型和页面信息架构
- 客户申请、屋顶照片和电费单上传
- 项目进度、合同、账单、消息和在线客服入口
- 底部导航、快捷功能卡片和移动任务流

阶段门槛：客户自主申请能进入既有项目状态机；客户只能看到所属客户组织的项目和账单；资料补充和状态变化可在客户端解释清楚。

## 阶段四：结算与外部能力模拟

- 固定分期和动态能源结算
- 月度账单快照、代扣记录、失败重试和账单调整单
- 电子签、支付/代扣、征信、IoT、资金方 Provider Adapter 的模拟实现
- 异步回调、验签、幂等、乱序、超时、限流、UNKNOWN 和人工复核场景
- 项目运营、能源数据和结清确认

阶段门槛：账单可重算但原账单不可覆盖；扣款失败不回退项目状态；满足期数、支付、无欠费/待调整并经财务确认后才能结清。

## 阶段五：后台完善与最终验收

- 运营指挥台、项目看板、风险异常、资金结算和报表
- 代理商客户漏斗、装机任务、渠道结算视图
- 资产卡片、运营监控和结清归档
- 备份恢复、性能、权限、敏感数据和审计检查
- 客户评审包和已知限制清单

## 测试策略

- 单元测试：状态转移、权限判断、账单计算、调整和结清条件
- 模块集成测试：数据库、对象存储、Outbox、回调处理和任务重试
- API 契约测试：OpenAPI 请求/响应、错误码、权限裁剪和幂等
- E2E 测试：客户自主申请、代理商代提交、审批拒绝、资料补充、签约失败、验收驳回、扣款失败和最终结清
- 每次演示前运行 `reset:demo`，确保流程从已知状态开始

## 最终验收剧本

1. 客户自主申请，提交屋顶和电费资料。
2. 代理商代客户创建另一项目并补充勘测材料。
3. 风控触发资料补充、审批拒绝和重新发起。
4. 电子签模拟成功与失败，签约失败回到待签约。
5. 项目进入建设、验收，验收驳回后整改并重新验收。
6. 项目并网进入运营/还款中，生成固定和动态账单。
7. 模拟扣款失败、重试、调整单和回调重复/未知结果。
8. 所有账单完成支付，财务确认后项目进入已结清。

真实支付、电子签、征信、IoT、电网和资金方生产接入不属于本路线的最终验收；它们在供应商、资质和账号确认后替换对应 Adapter。
